# SubTrack — Architecture

**Aplicație desktop pentru gestionarea abonamentelor personale**
*Desktop application for managing personal subscriptions*

A single-user Windows desktop app that keeps track of recurring subscriptions
(streaming, utilities, software, gym, …), reminds the user before payments and
trial expirations, and shows how much they spend per month and per year.

- **Language / UI:** Python 3.13 + PySide6 (Qt 6)
- **Storage:** SQLite, one local file in the user's app-data folder
- **No server, no account, no network required**

---

## 1. Layers

```
┌──────────────────────────────────────────────────────────┐
│ UI (PySide6)                                             │
│  MainWindow: Subscriptions · Dashboard · Reminders tabs  │
│  SubscriptionDialog · SettingsDialog · Tray · Notifier   │
└───────────────▲──────────────────────────────────────────┘
                │ calls services, never touches SQL
┌───────────────┴──────────────────────────────────────────┐
│ Services (application logic)                             │
│  SubscriptionService · StatsService · ReminderService    │
│  CurrencyService · ExportService · AutostartService      │
└───────────────▲──────────────────────────────────────────┘
                │ uses repositories + pure domain functions
┌───────────────┴──────────────────────────────────────────┐
│ Domain (pure Python, no Qt, no SQL)                      │
│  Subscription · BillingCycle · Category · Currency       │
│  billing.py: next payment date, monthly/yearly cost      │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│ Data                                                     │
│  Database (connection + migrations) · Repositories       │
└──────────────────────────────────────────────────────────┘
```

Rules:

1. **Domain** depends on nothing. It is fully unit-testable.
2. **Data** depends on domain only. It maps rows ⇄ dataclasses.
3. **Services** depend on domain + data. No Qt imports, so they are testable
   without a display.
4. **UI** depends on services. It never builds SQL or does date math itself.
5. `app.py` is the composition root: it creates the database, repositories,
   services and windows, and wires them together.

## 3. Data model

### Subscription

| Field                | Type            | Notes                                        |
|----------------------|-----------------|----------------------------------------------|
| `id`                 | int             | primary key                                  |
| `name`               | str             | "Netflix", "Gym", …                          |
| `price`              | Decimal         | stored as TEXT to avoid float rounding       |
| `currency`           | `Currency`      | RON / EUR / USD                              |
| `billing_cycle`      | `BillingCycle`  | WEEKLY / MONTHLY / QUARTERLY / YEARLY        |
| `first_payment_date` | date            | anchor for every future payment              |
| `category`           | `Category`      | streaming, music, software, utilities, …     |
| `trial_end_date`     | date \| None    | set while the subscription is a free trial   |
| `rarely_used`        | bool            | user flag → "consider cancelling" hint       |
| `active`             | bool            | cancelled subscriptions are kept as history  |
| `notes`              | str             | free text                                    |

The **next payment date is never stored**; it is computed from
`first_payment_date` + `billing_cycle` + today. That avoids having to
"advance" dates in the database after each payment.

Month arithmetic keeps the original day where possible and clamps to the end
of shorter months (31 Jan → 28/29 Feb → 31 Mar).

### Settings (key/value table)

| Key                    | Example | Meaning                               |
|------------------------|---------|---------------------------------------|
| `base_currency`        | `RON`   | currency used for totals and charts   |
| `reminder_days_before` | `3`     | how early payment reminders appear    |
| `rate_EUR`, `rate_USD` | `4.97`  | manual exchange rates, always in RON (1 EUR = 4.97 RON), so any base currency works |
| `start_with_windows`   | `0/1`   | unused: autostart state is read from the registry instead, so turning it off in Task Manager shows up in the app |

### SQL schema (version 1)

```sql
CREATE TABLE subscriptions (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    name               TEXT    NOT NULL,
    price              TEXT    NOT NULL,
    currency           TEXT    NOT NULL,
    billing_cycle      TEXT    NOT NULL,
    first_payment_date TEXT    NOT NULL,     -- ISO yyyy-mm-dd
    category           TEXT    NOT NULL,
    trial_end_date     TEXT,
    rarely_used        INTEGER NOT NULL DEFAULT 0,
    active             INTEGER NOT NULL DEFAULT 1,
    notes              TEXT    NOT NULL DEFAULT ''
);

CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

### Migration 2

```sql
-- each reminder (subscription + kind + due date) is shown only once
CREATE TABLE shown_reminders (
    subscription_id INTEGER NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,
    kind            TEXT    NOT NULL,    -- 'payment' | 'trial_ending'
    due_date        TEXT    NOT NULL,
    PRIMARY KEY (subscription_id, kind, due_date)
);
```

### Migration 3 (v0.2)

```sql
-- snoozing, and when a reminder was shown
ALTER TABLE shown_reminders ADD COLUMN shown_at TEXT;
ALTER TABLE shown_reminders ADD COLUMN snoozed_until TEXT;
UPDATE shown_reminders SET shown_at = due_date || 'T00:00:00';  -- v0.1 rows count as shown

-- payments the user marked as paid
CREATE TABLE payments (
    subscription_id INTEGER NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,
    due_date        TEXT    NOT NULL,
    paid_at         TEXT    NOT NULL,
    PRIMARY KEY (subscription_id, due_date)
);
```

Migrations are numbered and tracked with `PRAGMA user_version`. A test opens a
database made by v0.1 and checks that it upgrades without losing data.

## 4. Services

| Service               | Responsibility                                                        |
|-----------------------|-----------------------------------------------------------------------|
| `SubscriptionService` | add / edit / cancel / delete, validation, list with next payment date |
| `CurrencyService`     | convert any amount to the base currency using the manual rates        |
| `StatsService`        | monthly & yearly totals, totals per category, upcoming payments       |
| `ReminderService`     | due reminders (early, day-of, trial ending), snooze, mark paid, Reminders-tab timeline |
| `ExportService`       | export to CSV / JSON, import CSV / JSON (all-or-nothing, skips duplicates) |
| `AutostartService`    | start with Windows via `HKCU\…\CurrentVersion\Run`, launches `--minimized` |

## 5. Key flows

**Startup**
1. `paths.py` resolves `%APPDATA%\SubTrack\subtrack.db`.
2. `Database` opens it and runs pending migrations.
3. Repositories → services → `MainWindow` and `TrayIcon` are created.
4. The tray asks `ReminderService` for due reminders at startup and then every
   5 minutes; each becomes a notification (see below).

**Reminders**
- Each payment gets up to two reminders: *payment coming up* N days before
  (Settings, default 3) and *payment due today* on the day. Free trials get
  *free trial ending*. Each is shown once.
- On Windows the notification is a native toast with **Mark as paid**,
  **Remind me in 1 hour** and **Remind me tomorrow** (09:00). The day-of toast
  uses the "reminder" style, which stays on screen until acted on. Clicking the
  body opens the Reminders tab. If native toasts are unavailable, plain tray
  balloons (no buttons) are used.
- Button clicks arrive on a Windows thread; `Notifier.action_requested` (a Qt
  signal) moves them to the main thread, where `TrayIcon.handle_action` calls
  `ReminderService.mark_paid` / `snooze`.
- Buttons only work for a registered app identity, so at startup the app writes
  `HKCU\Software\Classes\AppUserModelId\SubTrack.App` (name + icon; per user,
  no admin). The installer removes it on uninstall.
- More than 4 reminders at once are combined into one summary notification.
- The **Reminders** tab lists every payment and trial end from 30 days back to
  30 days ahead with its status (Paid, Reminded, Snoozed, Due today, Upcoming,
  Not marked as paid); payments can be marked paid or unmarked there.

**Logging and self-test**
The app logs to `%APPDATA%\SubTrack\subtrack.log` (rotated at 500 KB), since
the .exe has no console. `SubTrack.exe --self-test` checks that Qt Charts and
the notification library load inside the package; `build.ps1` runs it.

**Closing the window** hides it to the tray instead of quitting, so reminders
keep working. "Quit" in the tray menu exits the app.

**Start with Windows**
The Settings checkbox writes a value to the per-user Run key (no admin
needed). Run from source it is `pythonw.exe src\subtrack\__main__.py --minimized`;
packaged as an .exe it is `SubTrack.exe --minimized`. With `--minimized` the
app starts hidden in the tray and only shows reminders.

**Import**
Every row is parsed and validated first; one bad row means nothing is
imported, and the error names the row. Rows identical to an existing
subscription (same name, price, currency, cycle, first date) are skipped.

**Adding a subscription**
`SubscriptionDialog` → `SubscriptionService.add()` (validates) →
`SubscriptionRepository.insert()` → table model refreshes → totals update.

## 7. Distribution

```
src/ ──PyInstaller (subtrack.spec)──▶ dist\SubTrack\SubTrack.exe  (+ _internal\ DLLs)
                                         │
                ┌────────────────────────┴───────────────────────┐
                ▼                                                ▼
   Inno Setup (installer\subtrack.iss)                   Compress-Archive
   dist\SubTrack-<v>-setup.exe                           dist\SubTrack-<v>-portable.zip
```

- **build.ps1** runs the whole chain locally; **.github/workflows/build.yml** runs it
  on `windows-latest` for every push, and publishes a GitHub Release for `v*` tags.
- **One-folder build**, not one-file: starts faster and trips antivirus less often.
  Unused Qt modules (Quick, QML, PDF, WebEngine, software OpenGL, …) are excluded,
  which brings the app folder from about 121 MB to 83 MB.
- **Installer** is per user (`PrivilegesRequired=lowest`) into
  `%LOCALAPPDATA%\Programs\SubTrack`, so no admin prompt. It offers a desktop icon
  and "start with Windows" (the same Run-key value the app's Settings write),
  removes that Run-key value on uninstall, and keeps the user's data.
- **Upgrades:** the fixed `AppId` makes a new installer upgrade the old one. The app
  holds a named mutex (`SubTrack.SingleInstance`) that the installer's `AppMutex`
  watches, so a running SubTrack is closed before files are replaced.
- **Version** lives only in `src/subtrack/__init__.py`; the spec (exe file
  properties), the installer (via `/DAppVersion`) and the release tag check all read it.
